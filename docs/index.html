horizontal scaling for solace pubsub+ cloud

How many brokers does this workload actually need?

Vertical scaling on Solace Cloud has a ceiling. When message sizes or adoption keep growing, the question stops being "which bigger service class" and becomes "how many brokers, and when." solace-autoscale answers it from a broker capacity model you compile yourself, with a pure, deterministic decision engine — and shows the reasoning instead of hiding it behind a number.

how it works

Compile a model, read the workload, get a defensible recommendation

Nothing is guessed and nothing is hidden. Capacity comes from measured numbers you compile to a versioned model; the decision is a pure function of that model plus live metrics; the report carries its provenance so a recommendation is still reproducible six weeks later.

01 / compile

Your numbers, versioned

A build step turns a performance workbook into versioned JSON. The runtime never reads a spreadsheet, and every decision records the model version that produced it.

02 / decide

Pure & explainable

Four capacity axes — messages, bytes, connections, spool — each with its own threshold. The engine reports the binding one, so you see why, not just how many.

03 / act (optional)

Recommend by default

Ships in recommend mode — the actuator isn't even constructed. Turn on scaling deliberately, behind a safety layer that refuses anything unsafe.

the thesis

One broker's ceiling collapses as messages get bigger

A single enterprise-10k broker sustains ~44,000 guaranteed 1 KB messages per second — but only ~439 per second at 200 KB. The curve is why "just add brokers" is sometimes the wrong answer: past a point you are byte-bound, and the cheaper fix is a smaller payload.

44,192 → 439
msg/s per broker, guaranteed
as payload grows 1 KB → 200 KB
Throughput falls ~100× while byte-rate barely doubles (45 → 90 MB/s). The broker is moving bytes, not messages — so the binding constraint flips to bytes, and adding brokers scales linearly against a cost that large payloads make brutal.

the business case

Broker counts become dollars, and dollars get projected

A recommendation an architect can defend needs a cost and a forward look. With an operator's own price table the report turns counts into monthly spend; the what-if re-runs the same pure engine under load multipliers to show where the fleet ceiling actually bites.

quickstart

Running in three commands

Until you compile your own model, everything runs against a clearly-labelled synthetic model that is blocked from any real action. Install, get a recommendation, project ahead. 

# install (Python 3.11+)
python -m venv .venv && . .venv/bin/activate
pip install -e '.[dev]'

# 1. compile your measured workbook into a versioned model (runs in CI too)
solace-autoscale compile --workbook performance.xlsx \
    --service-classes models/service-classes.json --out models/mymodel.json

# 2. get a recommendation, with the reasoning and cost
solace-autoscale recommend --config config.example.yaml --metrics metrics.json

# 3. project the fleet under 2x / 4x load
solace-autoscale whatif --config config.example.yaml --metrics metrics.json --multipliers 1,2,4

Other commands: simulate (validate the model across the full size × fanout matrix), monitor (scrape SEMP continuously and accrue accuracy history), accuracy (predicted vs actual), shard-advise (propose shard boundaries from an Event Portal export), serve (the assignment service).

customize

Every unresolved decision is a setting with a safe default

Configuration is one validated YAML file; unknown keys are rejected. The defaults are conservative, and each knob is documented. A few of the ones you will reach for first:

Fleet bounds

fleet.min_brokers / max_brokers

Clamp every recommendation. Hitting the ceiling is reported, never silently absorbed.

Topology

topology.mode: sharded | mesh | hybrid

Mesh adds inter-broker link cost to the bytes and spool axes — deliberately, so large payloads make mesh look as expensive as it is.

Headroom

policy.headroom.mode: derived | fixed

Derived headroom tightens the threshold to leave room for growth that arrives while a broker provisions. Your configured value is a ceiling, never a floor.

Billing & cost

billing.model · per_broker_monthly

Committed billing suppresses scale-down. Add your own price table to turn broker counts into monthly dollars; no pricing ships with the tool.

Metrics source

metrics.source: semp | prometheus | cloud-api | static

SEMPv2 field names are verified against a live broker; sources without a captured sample are documented stubs rather than guesses.

Actuation

actuation.mode: recommend | scale-up-only | full

Defaults to recommend, and stays there. Turning on scaling is a deliberate edit, behind a kill switch, rate limits, and pre-delete safety checks.
